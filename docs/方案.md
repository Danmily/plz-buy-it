# 智能挽单 · 两周 MVP 方案

> 命题：在用户购物犹豫时出手。通过 AI 识别用户在商详、加购、结算流程中的犹豫信号，判断当下的核心顾虑，在关键节点给出差异化挽留动作，用精准的个性化挽留替代一刀切的弹窗优惠。
>
> Demo：[`index.html`](../index.html)（三段会话回放，数字均为示意）

---

## 0. 一句话

**AI 负责判断"该不该出手、为什么犹豫、在哪出手"，用户看到的是平台真实数据做成的事实卡片。**

和一刀切相比，价值来自两头：对症的人转化更高，不需要挽留的人不再浪费券和打扰。

---

## 1. 两个核心判断

### 1.1 颗粒度：从"人群×规则"下沉到"人×这次购物×这件商品×这个时刻"

以前的挽单（加购未付推券、结算页退出弹窗）本质是人群规则粒度：满足条件的一批人收到同一个动作，uid 只是投递单位。精细化要同时往两个方向下沉：

- **时间上**：uid 长期画像是慢变量（T+1），"这次购物"是快变量。比价、反复回访、加购后转投他款这类犹豫信号只存在于同一会话的事件之间，单条事件、单个 uid 标签都表达不出来。
- **意图上**：从"会不会流失"（二分类）细化到"为什么犹豫"（顾虑多分类）和"该不该出手"。

一条样本 = `(uid, session_id, item_id, 决策时刻 t)`，挂上 t 之前的会话序列、uid 画像、商品上下文。

### 1.2 动作有限，所以意图要准，但还要补两件事

- **顾虑分类从动作库反推。** 两类顾虑对应同一个动作就合并；没有动作能接的顾虑归入"不打扰"。分类粒度 = 动作粒度。
- **"该不该出手"和"为什么犹豫"同等重要。** 犹豫的人里有人不挽也会买（发券是浪费），有人怎么挽都不买（打扰是负体验）。

---

## 2. 整体链路

```
原始埋点 → 会话切分 + 序列文本化 → 犹豫信号抽取(规则) → 转化概率打分(轻量模型)
        → LLM 顾虑归因(带证据) → 动作映射 + 频控 → 单会话回放 / 群体看板
```

借鉴 AI 大侦探"原始日志 → 中间结果 → 结论"的骨架，差异点：

| | AI 大侦探 | 智能挽单 |
|---|---|---|
| 时机 | 事后，按需查询 | 事中，会话第 N 步就判断 |
| 产出 | 报告、结论 | 顾虑 + 动作 + 证据 |
| 规模 | 单人深挖 | 批量，先用便宜模型筛掉不需要 LLM 的会话 |
| 验证 | 人工看报告 | 用事后行为反向验证 |

## 3. 数据准备

### 3.1 统一 schema（后续换命题方数据只改适配层）

**事件表**（一个事件一行）：

`uid_hash, session_id, ts, page(商详/购物车/结算/搜索/直播间/短视频), event_type, spu_id, sku_id, price_shown, coupon_shown, duration_ms, source(内容场/货架/搜索), extra(json)`

- **会话切分**：同一 uid 相邻事件间隔超过 30 分钟切开（可调）；多商品会话以"焦点商品"（停留最久或加购的）组织样本。
- **决策时刻 t**：商详离开未加购；购物车停留后离开；结算页未提交退出；加购后 N 小时未结算。
- **标签**：
  - `y_convert`：t 之后 24h/72h 内是否购买该 SPU（同类替代品另记一列）。天然标签，用于训练打分模型。
  - `y_reason`：顾虑类别，无天然标签，见 3.3。

### 3.2 数据清单（按优先级）

| 优先级 | 数据 | 用途 | 要确认的点 |
|---|---|---|---|
| P0 | 商详、购物车、结算埋点明细 | 序列主体 | 停留时长、点评价/筛差评、切换 SKU、展开优惠明细、购物车勾选/取消、改地址/换支付/支付失败是否有埋点 |
| P0 | 订单、支付表 | `y_convert` | 剔除退款单 |
| P0 | 商品维表 | 类目、价格、评分 | |
| P1 | AI 用户画像 46 字段 | 消费等级、生命周期、八大人群、`user_preference_info` 自然语言总结，进 LLM prompt 做长期侧写 | 差异化来源 |
| P1 | 电商 DMP 交易与支付、新老客与流失分层 | 打分模型特征 | 时间窗预置，取 7/30 天即可 |
| P1 | 价格/优惠敏感类标签 | 价格顾虑先验 | 电商侧无现成标签则用券核销历史计算 |
| P1 | 价格历史、差评率/关键词、发货时效、运费险/7 天无理由、退货率 | 顾虑的客观依据 | |
| P1 | 现有挽留策略配置与效果数据；领券/核销/触达/点击历史 | 离线反事实验证、频控、券疲劳 | 需要用户级明细，并确认是否有对照组 |
| P2 | 客服 IM 咨询文本 | 质量最高的顾虑标签 | 合规确认，仅安全域内使用 |
| P2 | 搜索 query | "平替""A 和 B 哪个好"等比价信号 | |
| P2 | 同类商品退货、差评原因 | 品类已知风险点 | |

**合规底线**：uid 全程 hash，明细不出安全域，LLM 使用内部合规模型；药品、母婴、医疗器械等敏感类目排除。

### 3.3 顾虑标签来源

1. **事后反标**：用 t 之后 7 天行为倒推当时顾虑（弱标签，可批量）。
   - 降价或领券后买了同款 → 价格
   - 离开后买了同类其他商品 → 比价、选择困难
   - 离开前看了差评且没买 → 品质信任
   - 问客服尺码或换 SKU 下单 → 规格适配
   - 支付失败或改地址后退出 → 流程摩擦
   - 7 天内未再触达该类目 → 需求不强
2. **客服文本**：精度高、覆盖低，用于校验。
3. **人工金标集**：300 条会话双人盲标，算一致性；一致性低的类别合并。

### 3.4 顾虑分类 v0（从动作反推）

| 顾虑 | 典型信号 | 动作 |
|---|---|---|
| 价格 | 展开优惠明细、领券未用、价格处于高位、反复回访、画像价格敏感 | 定向券、价保说明、降价提醒 |
| 等大促 | 临近大促、加购不买 | 价保（降价退差） |
| 凑单满减 | 购物车金额接近门槛 | 凑单推荐 |
| 比价、选择困难 | 同会话看多个同类商品、搜对比词 | 对比卡片、榜单 |
| 品质信任 | 看差评、看买家秀、新店或低评分、高客单 | 精选好评、正品保障、测评短视频 |
| 规格适配 | 反复切 SKU、看尺码表 | 尺码助手、同身材买家评价 |
| 物流售后 | 看发货时间、退换说明 | 发货时效、运费险、7 天无理由 |
| 流程摩擦 | 支付失败、改地址、结算页长停留 | 支付方式引导、客服兜底（不发券） |
| 不挽 | 随便逛（无深度行为）或大概率会买（高意向老客） | 不出手 |

每个会话输出一个主顾虑、一个次顾虑和置信度，允许"不确定"。

### 3.5 范围收窄

- **类目**：选 2 个顾虑结构差异大的，如服饰鞋包（规格为主、决策快）与 3C 数码（比价、品质为主、决策慢）。
- **样本**：近 2～4 周，抽 2～5 万个决策时刻。
- **分层报指标**：高活、中活、低活、新客各自独立。

## 4. 模型

1. **信号抽取（规则）**：20～30 条可解释的犹豫信号，每条映射到顾虑先验，也是给 LLM 的"中间结果"。
2. **转化概率打分（LightGBM）**：特征 = 会话统计 + 信号 + 画像标签 + 商品特征；标签 = `y_convert`。按 p 分三段：
   - 必买区（p 高）：不挽
   - 弱需求区（p 极低）：不挽
   - 犹豫区（中间）：送 LLM 归因
3. **LLM 顾虑归因（prompt + few-shot，不微调）**：
   - 输入：带编号的会话序列、触发信号、画像总结、商品上下文
   - 输出 JSON：主/次顾虑、置信度、**证据事件编号**、推荐动作、不确定说明
   - 证据编号由程序校验是否真实存在，防幻觉
   - 用金标集迭代 prompt 2～3 轮

**实时性**：MVP 用 T+1 离线日志回放，在会话第 N 个事件截断、只用 t 之前的信息模拟事中判断（严防特征穿越）。真实时链路是后续工作。

## 5. 挽留内容：怎样被用户认可

### 5.1 原则：AI 负责"选"，数据负责"说"，模板负责"呈现"

AI 生成的挽留内容容易被抵触，原因有四个：

1. 暴露"我在盯着你"。识别结果只决定选什么内容，永远不写进文案。
2. 无法验证。"超划算"没法核实；"比 30 天均价低 ¥42"点开能看到曲线。
3. 营销腔，用户早已免疫。
4. 写错一次就失信，价格类表述还涉及合规口径。

例外：用户主动发起时（点"帮我对比""问问 AI"），AI 生成内容是被接受的。平台主动推送的，一律用事实。

### 5.2 可信度梯度

| 内容类型 | 举例 | 可信度 | 成本/副作用 |
|---|---|---|---|
| 平台客观数据 | 价格走势、发货时效、销量 | 最高 | 几乎为零 |
| 其他买家的声音 | 同尺码反馈、高赞评价、问大家 | 高 | 评价要有代表性 |
| 平台保障 | 价保、运费险、7 天无理由、正品 | 高 | 部分有成本 |
| 利益 | 券、满减 | 有效 | 贵，养出"加购等券"用户 |
| AI 生成建议 | 对比结论、购买建议 | 被动推送时最低 | 只适合用户主动请求 |

**前三档能解决的不动券。**

### 5.3 1～3 秒能讲清的信息

公式：**一个数字或事实 + 一个来源 + 一个按钮。**

| 顾虑 | 一眼信息 | 触点 | 来源 |
|---|---|---|---|
| 价格 | 比 30 天均价低 ¥X、加购后已降 ¥X、券后到手价 | 商详价格区小条、购物车降价角标 | 价格历史 |
| 等大促 | 价保 30 天，降价退差 | 购物车、结算页 | 价保规则 |
| 凑单满减 | 再买 ¥X 减 ¥Y + 凑单推荐 | 购物车 | 满减规则 |
| 比价 | 看过的 2～3 款，到手价/评分/发货对比 | 离开后再曝光、对比入口 | 浏览记录 + 商品维表 |
| 品质信任 | 好评率 + 一条高赞评价 + 回购率 | 商详评价区置顶 | 评价 |
| 规格适配 | 同身高体重买家 X% 选 M | 尺码选择区 | 尺码反馈、退货原因 |
| 物流售后 | 预计明天送达、运费险 | 结算页 | 履约数据 |
| 流程摩擦 | 换个支付方式试试 | 结算页 | 支付日志 |

**内容型挽留**（抖音电商场景的差异点）：品质和规格顾虑可以用该商品的真实测评短视频、直播讲解切片回应。

### 5.4 触点按时机分四类

| 时机 | 触点 | 打扰程度 | 用法 |
|---|---|---|---|
| 还在页面里 | 页内信息条、角标、尺码区提示 | 最低 | 优先用 |
| 正在离开 | 返回挽留弹窗、结算退出弹窗 | 最高 | 仅高置信、高价值会话，每人每天封顶 |
| 已经离开 | 推荐流再曝光、降价提醒、站内信、push | 中 | 推荐流再曝光最自然，push 严格频控 |
| 用户主动问 | 智能导购、对比助手 | 低 | AI 生成内容的主场 |

## 6. 效果验证（无线上 AB 的三层证据）

1. **识别准不准**：金标集 top-1/top-2 准确率，按类目×活跃度分层；证据可溯源率接近 100%。
2. **归因与事后行为是否一致**：判为"价格顾虑"的用户，后续降价或用券后购买的比例应显著高于其他组；判为"比价"的用户后续购买同类替代品比例更高。
3. **比一刀切好在哪**（依赖命题方历史挽留数据）：
   - 把收到统一挽留券的人群按模型切开，"价格顾虑"组的券后转化增量若明显更高，说明定向发券可在不损失转化的前提下省券。
   - "必买"组收券前后转化相近，可直接算出可节省的券成本。

## 7. 两周排期（10 个工作日）

| 时间 | 内容 | 产出 | 风险 |
|---|---|---|---|
| D1–2 | 对齐顾虑分类 v0 和动作库；数据清单、提权限；确认关键埋点；向命题方要历史挽留数据 | 分类 v0、schema、数据清单 | 权限审批慢 |
| D3–4 | 会话切分、序列文本化、信号抽取、关联画像与商品 | 决策时刻宽表 | 特征穿越 |
| D5–6 | 打分模型 v1；LLM 归因 prompt v1；标注 300 条金标集 | 模型、金标集 | 一致性低则合并类别 |
| D7 | 端到端跑通，第一版三层评估 | 评估 v1 | 命题方数据到位即替换 |
| D8–9 | prompt 迭代、bad case 分析；demo（单会话回放 + 群体看板） | demo | |
| D10 | 复盘、答辩材料、彩排 | 答辩稿 | |

**分工**：数据（SQL、埋点、宽表）/ 模型（LightGBM + LLM 归因）/ 产品（分类、标注、demo、对接业务）。

## 8. 业务对接清单

**会议目标**：带走三样东西：可用触点、用户级效果数据、验收口径。

**会前准备**：

1. 一页纸：问题、方案一句话、两周产出、需要业务提供什么。
2. 现状截图：走一遍"商详 → 加购 → 结算 → 退出"，截下现有挽留触点并标注"已有 / 想改哪里"。
3. 触点×顾虑矩阵草稿（5.3 表），会上请业务逐格标注。
4. 一个 mock 案例（即本仓库 demo）。

**要问的问题**：

- 触点和内容
  - 线上在跑的挽留触点有哪些？触发规则、频控、量级、点击/关闭/转化？
  - MVP 阶段哪些触点可换内容做演示或小流量？是否需要审核，周期多长？
  - 价格类表述的合规口径？
  - 业务最担心什么：打扰投诉、券成本，还是品牌风险？
- 数据
  - 历史挽留效果有无用户级明细（谁收到、收到什么、是否点击/关闭/转化）？
  - **有没有对照组（holdout）？**
  - 关键埋点是否存在；日志时效是 T+1 还是小时级；客服文本能否使用；画像与 DMP 标签的使用审批路径。
- 效果和验收
  - 哪几类顾虑最多、哪个类目挽单最痛？
  - 两周后什么结果算通过？谁来验收？
  - 固定对接人和答疑节奏。

**会上不做**：不把"AI 生成个性化文案"当标题；不承诺线上 AB 和实时链路；不讲模型细节。

**会后落地**：触点清单（MVP 可用 / 仅演示 / 不可用）；数据清单与对接人；一句话验收标准，发群确认。
