# 测试集 v0：出手判断 + 顾虑归因

合成数据，222 条。用来在真实金标集到位前，把 prompt、输出格式、决策规则和评测脚本先跑通。

> **限制**：顾虑信号来自模板，关键词规则就能把单顾虑类识别到 99%，所以单顾虑类只能测格式和稳定性，**不能代表真实准确率**。真正有区分度的是"不出手"和"陷阱"两层。真实准确率要靠 300 条真实会话的人工金标集。

## 文件

| 文件 | 说明 |
|---|---|
| `gen_testset.py` | 生成器，固定随机种子，可复现；`--ablate profile` / `--ablate item` 生成消融版本 |
| `testset_v0.jsonl` | 完整版 |
| `testset_v0_no_profile.jsonl` | 去掉画像（测画像的必要性） |
| `testset_v0_no_item.jsonl` | 去掉商品上下文（测价格历史等的必要性） |
| `score.py` | 打分，按层、按标签分组报指标 |
| `baseline_keywords.py` | 关键词规则基线，模型必须明显超过它 |

## 分层

| 层 | 条数 | 考什么 |
|---|---|---|
| L1 清晰 | 48 | 单一顾虑、信号明确：格式和稳定性 |
| L2 干扰 | 48 | 混入无关浏览、一条其他顾虑的弱信号 |
| L3 双顾虑 | 30 | 两类顾虑，主顾虑信号更多：主次排序 |
| L4 稀疏 | 16 | 低活、新客只有一条信号：是否诚实表达不确定 |
| L5 陷阱 | 26 | 画像说价格敏感但行为全是尺码；已是 30 天最低价；加购等券型用户 |
| N 不出手 | 54 | 必买、弱需求、已买替代品、频控、敏感类目 |

## 每条用例的字段

- `query`：送给模型的输入文本（画像 + 商品上下文 + 带编号的行为序列 + 决策时刻）
- `events` / `profile` / `item`：结构化原始数据，可以直接拿去做打分模型的特征
- `gold`：标准答案
  - `act`、`act_reason`：该不该出手及原因
  - `primary`、`secondary_ok`：主顾虑、可接受的次顾虑
  - `evidence`：主顾虑的证据事件编号
  - `action_ok`：可接受的动作
  - `must_not`：禁区（例如非价格顾虑不准发券；画像冲突题不准答价格）
  - `allow_uncertain`：稀疏样本，允许回答不确定

## 模型输出格式

```json
{"id": "C001", "act": true, "primary": "价格", "secondary": "比价", "confidence": 0.7,
 "evidence": [3, 5], "action": "定向券", "uncertain": false}
```

- 顾虑取值：价格、等大促、凑单、比价、品质信任、规格适配、物流售后、流程摩擦、无
- 动作取值：定向券、价格事实、价保、凑单推荐、对比卡片、好评与保障、尺码与规格助手、时效与运费险、支付引导、无

## Prompt 模板（system）

```
你是电商挽单决策助手。输入是一位用户截至决策时刻的购物会话。请判断：
1. act：现在该不该出手挽留。以下情况不出手：必买（复购周期内直达常买款、无犹豫行为）；
   弱需求（停留很短、无深度行为）；已买替代品；近期挽留触达多次且都被关闭（频控）；
   药品、母婴、医疗器械等敏感类目。
2. primary / secondary：主、次顾虑。以本次会话行为为准，画像只作先验，不能压过行为证据。
3. evidence：支撑主顾虑的事件编号，只能引用输入中存在的编号。
4. action：只有价格顾虑可以用「定向券」；当前价已是近 30 天最低、或用户有「加购后等券」习惯时，
   用「价格事实」或「价保」代替发券。
5. 证据不足时 uncertain=true，confidence 不超过 0.6。
只输出 JSON，字段：act, primary, secondary, confidence, evidence, action, uncertain。
```

## 怎么跑

```bash
python3 eval/gen_testset.py
python3 eval/baseline_keywords.py eval/testset_v0.jsonl > preds_baseline.jsonl
python3 eval/score.py eval/testset_v0.jsonl preds_baseline.jsonl
```

自己的模型：对每条 `query` 调用模型，按上面的格式写 `preds.jsonl`（带 `id`），再跑 `score.py`。

## 关键词基线成绩（模型的下限）

| 指标 | 全部 | L5 陷阱 | N 不出手 |
|---|---|---|---|
| 出手判断 | 88% | 100% | 52% |
| 主顾虑 top1 | 99% | 100% | 100% |
| 动作正确 | 90% | 38% | - |
| 误发券 | 10% | 62% | 11% |

基线在"已买替代、频控、敏感类目"上出手判断为 0%，在"已是低价、加购等券"上误发券 100%。这几项就是模型要拉开差距的地方。

## 数据消融

用三个版本分别跑同一个模型，对比指标：

- 去掉画像后，必买、频控、加购等券几项应该明显下降。如果没降，说明模型没在用画像。
- 去掉商品上下文后，"已是低价"应该下降（看不到 30 天最低价）。
- 某类数据去掉后指标几乎不变，就把它从"重要"降为"可选"。
