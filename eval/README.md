# 挽单评测体系

一条命令完成：调用被测模型 → 逐条打分 → 诊断 → Markdown 报告 → 按错误分布生成下一轮训练数据。

```bash
python3 eval/pipeline.py --backend baseline                       # 不需要模型，确认流程能跑通
LLM_API_KEY=xxx python3 eval/pipeline.py --backend openai \
  --base-url https://<OpenAI 兼容接口>/v1 --model <模型或接入点> --name prompt-v2
python3 eval/pipeline.py --backend cmd --cmd "python3 my_model/predict.py"   # 自己的程序
python3 eval/pipeline.py --backend preds --preds my_preds.jsonl              # 已有预测
```

在 Claude Code 里直接说「跑一下挽单评测」也可以，会走 `.claude/skills/retention-eval`。

## 产出（`eval/runs/<时间>_<名称>/`）

| 文件 | 内容 |
|---|---|
| `report.md` | 结论、核心指标与及格线、分层 / 场景 / 渠道 / 品类表现、混淆矩阵、出手判断分解、数据消融、改进建议、错误样例 |
| `metrics.json` | 全部汇总指标和建议，供下次对比 |
| `results.jsonl` | 逐条打分结果 |
| `preds.jsonl` / `raw_outputs.jsonl` | 解析后的预测、模型原始输出 |
| `train_data/` | `sft.jsonl`（微调用 messages）、`cases.jsonl`（结构化字段 + 答案，可做打分模型特征）、`plan.json`（分配与泄漏检查） |

## 测试集 v1（320 条，合成）

| 层 | 条数 | 覆盖 |
|---|---|---|
| L1 清晰 / L2 干扰 | 32 / 48 | 8 类顾虑；干扰层混入无关浏览、"像信号的无关行为"（看好评、切后台、收藏）、多商品浏览、一条其他顾虑的弱信号 |
| L3 双顾虑 | 30 | 主次排序 |
| L4 稀疏 | 16 | 只有一条信号时是否诚实表达不确定 |
| C 对话 | 56 | 显式顾虑、隐含表达（"学生党预算有限"）、对话与行为冲突（亲口说的优先）、"再想想" |
| L5 陷阱 | 58 | 画像与行为冲突、已是 30 天最低价、加购等券、多商品焦点混淆、直播限时价、高客单分期、新客首单信任、送礼 |
| N 不出手 | 80 | 必买、弱需求、已买替代、频控、敏感类目、囤货型、用户拒绝、非购物意图 |

覆盖 6 种入口（搜索、推荐流、短视频、直播间、push 召回、店铺）、4 个决策时刻（商详离开、加购后离开、购物车离开、结算页退出）、6 个品类、4 档活跃度。

**防泄漏**：测试集和训练数据用两套不重叠的商品与品牌，且每组表述按奇偶位拆分，测试集里的说法在训练数据中不会出现。`gen_train.py` 每次都会做泄漏检查。

**基线**：关键词规则全部判对 31%，主顾虑 top1 73%，误发券 18%。模型至少要明显超过它。

## 模型输出格式

```json
{"act": true, "primary": "价格", "secondary": "比价", "confidence": 0.7, "evidence": [3, 5],
 "action": "定向券", "touchpoint": "push", "uncertain": false, "reply": ""}
```

取值和规则见 [`prompt.md`](prompt.md)。`touchpoint`、`reply` 可选，给了才评。

## 指标

| 指标 | 含义 |
|---|---|
| 出手判断 | 该不该挽留判断对了 |
| 主顾虑 top1 / top2 | 主顾虑命中；top2 = 主或次命中 |
| 动作正确 / 触点正确 | 动作、触点在可接受范围内 |
| 证据召回 / 证据编号合法 | 列出的证据覆盖多少标准证据；编号是否真实存在 |
| 踩禁区 / 误发券 | 给了明令禁止的答案；不该发券时发券 |
| 稀疏样本过度自信 | 证据很少却给出高置信度 |
| 回复数字可溯源 / 暴露推断或营销腔 / 不该回复却回复 | 对话回复只用输入里的数字、不提"看您犹豫"、不出手时不回复 |
| 全对 | 核心决策项全部正确（证据召回不足一半也算错） |

及格线在 [`config.json`](config.json)，是团队提议值，待业务确认。

## 自己的程序接入（cmd 后端）

stdin 每行一个用例（已去掉答案），含 `id`、`query`、`profile`、`item`、`events` 等结构化字段；stdout 每行输出一个预测 JSON（带 `id`）。打分模型可以直接读结构化字段，不必解析文本。

## 训练数据

```bash
python3 eval/gen_train.py --from-run eval/runs/<某次> --n 2000   # 按该次错误分布加量
python3 eval/gen_train.py --n 2000                                 # 均匀生成
```

分配方式：每个场景先给一份基础量，再按该场景的错误率和诊断建议加量；15% 是最小对比对（同一段会话只改一个条件，答案翻转），专门教模型分清"低价 / 非低价""买了替代 / 没买""有 / 无频控""拒绝 / 再想想"这几条边界。

## 局限

- 合成数据检查的是决策规则、输出格式和典型陷阱；真实准确率要用 300 条真实会话的人工金标集衡量。真实数据到位后，按 `events` 的字段写适配层，就能沿用同一套打分和报告。
- 训练集和测试集出自同一套场景设计，测试集上的提升不等于线上提升。
- 回复类指标只查数字溯源和禁用表述，不评价说服力。
